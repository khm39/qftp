qftp-web-bridge(WebTransport ブリッジ)

作成日: 2026-09-03 更新日: 2026-09-03

概要

機能名

qftp-web-bridge: ブラウザから qftp を利用するための WebTransport(HTTP/3)終端。Phase 7。

目的

クライアント証明書を出せないブラウザに、ベアラトークン認証で同じストレージを公開する。転送エンジンを共有し、ネイティブとの機能差(再開・圧縮・Cd)をなくす。

想定ユーザー

ブラウザ利用者(Chrome / Edge / Firefox。Safari は WebTransport 非対応)。

利用シーン

  1. 社内ポータルからのファイル取得。
  2. 外部協力者へのアップロード窓口(トークン + origin 制限)。

スコープ

含むもの

  • WebTransport セッション受付、origin 検査、トークン認証(ハッシュ照合、失敗レート制限)。
  • 1 双方向ストリーム = 1 Request、セッション単位の cwd 保持。
  • 転送エンジンの tokio ホスト実装(再開・圧縮対応)。
  • SPA の静的配信(開発用、hyper)。

含まないもの

  • mTLS。
  • ネイティブサーバへのプロキシ(直接ストレージを扱う)。
  • サーバとブリッジ間のクォータ共有(別プロセスのため独立。運用設計書に制約を記載)。

前提条件

トランスポートは wtransport(quinn + tokio)で確定(ADR-006)。quiche の h3 は拡張 CONNECT までしか実装しておらず、WebTransport のストリーム振り分けを外側から足せないことを調査で確認済み。

機能要件

主要フロー

  1. CONNECT 受理 → origin 検査 → :path の token= をハッシュ照合 → ユーザ確定(10 s 以内)。
  2. セッション状態(user、cwd)を作成。
  3. 双方向ストリームごとに Request をデコード → ACL → メタデータ操作(spawn_blocking)または転送エンジン(tokio ホスト)。

入力

設定: cert / key、bind(UDP 4433)、root、users、tokens、http_bind(開発用)、allowed_origins、limits.max_sessions(256)、limits.max_streams_per_session(64)、limits.auth_failures_per_ip。

出力

ワイヤ応答(qftp/1 と同一)、ログ、メトリクス(サーバと同名 + qftp_web_sessions_open、qftp_web_auth_failures_total)。

ビジネスルール

  • origin ポリシー: 未設定 → 非ブラウザ許可、ブラウザはトークン認証時のみ、anonymous では拒否。* → 全許可。リスト → 正規化完全一致。
  • トークンはハッシュ保存、定数時間照合、per-IP の失敗レート制限。
  • anonymous は read-only。
  • SPA 配信は開発用。本番は静的ホスティングまたはリバースプロキシ。

異常系・例外処理

  • origin 不許可 / トークン不正: CONNECT を 403 で拒否。
  • 認証タイムアウト: セッション close。
  • セッション・ストリーム上限: 受付拒否。

ロギング・監視

影響範囲・連携

影響する既存機能

  • 転送エンジン(tokio ホスト)。
  • qftp-admin(tokens.toml)。
  • 画面設計書(Web クライアント)。

外部システム連携

リバースプロキシ(nginx 等、静的配信のみ。WebTransport は中継されない)。

データモデル変更

tokens.toml(ハッシュ形式)。

リスク・代替案

リスク

  • quinn 系スタックがワークスペースに残る(MSRV 差、依存重複)。ブリッジをビルドしない構成(feature / 別ワークスペース)を用意して、ネイティブだけの利用者に負担を掛けない。
  • ブラウザ側の codec / BLAKE3 / zstd を JS で持つか WASM で共有するかで保守性が大きく変わる。

代替案と棄却理由

  • ブリッジを廃止し、ブラウザ利用は WebDAV 等の別プロダクトに委ねる。
  • qftp-wire + blake3 + zstd を WASM 化して SPA と共有(推奨、Phase 7 で評価)。
