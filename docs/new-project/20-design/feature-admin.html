機能設計書

qftp-admin(管理 CLI)

作成日: 2026-09-03 更新日: 2026-09-03

概要

機能名

qftp-admin: users.toml と tokens.toml を安全に編集する運用 CLI。

目的

手編集による構文・意味エラー(未知キー、home の入れ子、quota_bytes = 0 など)を防ぎ、サーバが読める形式で原子的に書き込む。

想定ユーザー

サーバ運用者。

利用シーン

  1. ユーザ追加と権限設定。
  2. クォータ変更。
  3. Web ブリッジ用トークンの発行・失効(ハッシュ保存)。

スコープ

含むもの

  • init-users、add-user、remove-user、list-users、set-permissions、set-quota(プロトタイプ互換)。
  • 追加: set-anonymous([anonymous] の設定 / 削除)、token add|revoke|list(tokens.toml、ハッシュ保存)、check(サーバと同じ検証器で両ファイルを検証)。
  • 書込後のファイルモードを指定可能(--mode 0640、既定 0600)。

含まないもの

  • 実行時の管理(接続の kick、reload)。
  • 証明書の発行。

前提条件

スキーマは qftp-core::user の型が唯一の正本で、admin はそれを serde で読み書きする(キー順は PERM_KEYS で安定化)。

機能要件

主要フロー

  1. 対象ファイルを読み、toml_edit で構造を保持したまま編集。
  2. qftp-core の検証器で結果を検証。
  3. 同一ディレクトリの temp に書き、fsync、rename。

入力

--users <path>(既定 /etc/qftp/users.toml)、--tokens <path>(既定 /etc/qftp/tokens.toml)。各サブコマンドの引数はプロトタイプ互換(add-user <name> [--home] [--read=true] [--write] …、set-quota <name> --bytes N | --unlimited)。

出力

編集済みファイル(コメント保持)。list-users / token list は表形式または --json。終了コード: 0 / 64 usage / 65 検証失敗 / 74 I/O。

ビジネスルール

  • anonymous は予約名。
  • トークンは生成時のみ平文を表示し、ファイルにはハッシュ(argon2id または SHA-256、実装時に決定)と作成日・ラベルを保存。
  • 検証規則はサーバと同一(共有コード)。

異常系・例外処理

  • ファイル未存在(init-users 以外): 65。
  • 重複ユーザ / 未知ユーザ: 65。
  • 書込権限なし: 74。

非機能要件

セキュリティ

  • temp は 0600 で作成、rename 後に指定モードへ。
  • トークン平文をログ・履歴に残さない(表示は 1 回)。

影響範囲・連携

影響する既存機能

サーバ・ブリッジのファイル読込(スキーマ共有)。

外部システム連携

N/A

データモデル変更

tokens.toml のスキーマがハッシュ形式に変わる(プロトタイプの平文形式とは非互換。リリース前のため許容)。

リスク・代替案

リスク

ハッシュ方式の選定(argon2id は照合コストが高く、ブリッジの接続受付で DoS 面が増える。SHA-256 + 高エントロピートークンで十分という判断もあり得る)。

代替案と棄却理由

トークンをサーバ側で生成せず運用者が持ち込む(プロトタイプ方式): 低エントロピートークンを防げないため、生成を既定にする。
