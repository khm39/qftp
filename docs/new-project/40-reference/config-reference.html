優先順位と読み込み規則

プログラム既定の設定ファイル優先順位(高 → 低)
qftp-server/etc/qftp/server.toml(--config で上書き。ファイルがなければ既定値のみ)CLI フラグ > 設定ファイル > 組込既定
qftp-client~/.qftp/config.toml(--config)CLI フラグ > コマンドライン URL > [host.alias] の明示キー > [host.alias].endpoint > [defaults] > 組込既定
qftp-admin/etc/qftp/users.toml、/etc/qftp/tokens.toml(--users、--tokens)CLI フラグのみ
qftp-web-bridge(Web 区分)/etc/qftp/web-bridge.tomlサーバと同じ
規則内容
未知キーエラー(deny_unknown_fields)。綴り間違いを黙って無視しない
パス~/ を展開。相対パスは設定ファイルのディレクトリ基準ではなくプロセスの cwd 基準(systemd では絶対パスを使う)
サイズ表記整数(バイト)または文字列 "10M"(K / M / G = 10 の累乗、Ki / Mi / Gi = 2 の累乗)
時間表記文字列 "30s"、"5m"、"1h"
環境変数RUST_LOG(tracing フィルタ、設定の log.level より優先)、HOME / XDG_STATE_HOME(既定パス)。設定値を環境変数で上書きする仕組みは持たない
--check-configファイルとフラグを読んで検証し、正規化した有効設定を TOML で stdout に出力して終了(0 = OK、1 = エラー)。秘密は含まない

qftp-server: server.toml

# /etc/qftp/server.toml — 全キーを既定値つきで示す(省略可能)
bind = "127.0.0.1:4433"          # UDP。必須ではないが本番では 0.0.0.0 / [::] を明示
root = "/srv/qftp"               # 必須。canonicalize される
users = "/etc/qftp/users.toml"   # 省略時は anonymous(read-only)のみ
require_retry = false
metrics_bind = "127.0.0.1:9090"  # 省略時は無効
shutdown_timeout = "30s"

[tls]
cert = "/etc/qftp/server.crt"    # self_signed = false のとき必須
key = "/etc/qftp/server.key"     # owner-only(0600 / 0400)かつ euid 所有
client_ca = "/etc/qftp/ca.crt"   # 指定すると mTLS 必須
self_signed = false
self_signed_persistent = false   # self_signed = true のときのみ有効
state_dir = "$XDG_STATE_HOME/qftp/self-signed"

[limits]
max_connections = 64
max_connections_per_ip = 8
initial_rate_rps = 50.0
initial_rate_burst = 100.0
request_rate_rps = 50.0
request_rate_burst = 100.0
max_file_size = "1Gi"
blocking_threads = 0             # 0 = CPU 数 × 2
max_streams_bidi = 4
idle_timeout = "30s"
half_open_timeout = "5s"
ls_page_entries = 10000
ls_page_bytes = "1Mi"

[log]
format = "text"                  # "text" | "json"
level = "info"                   # RUST_LOG が優先
キー型既定検証 / 備考対応フラグ
bindSocketAddr127.0.0.1:4433起動直後に解釈(TLS 生成前)--bind
rootpath必須存在するディレクトリ。canonicalize--root
userspathなしファイル形式リファレンス参照。読めなければ起動失敗--users
require_retryboolfalse--require-retry
metrics_bindSocketAddrなし非 loopback は警告--metrics-bind
shutdown_timeoutduration30sgraceful の上限--shutdown-timeout
tls.cert / tls.keypath必須(自己署名でない場合)PEM。鍵は group / other ビットなし、euid 所有(root 除く)--cert / --key
tls.client_capathなしPEM バンドル。指定で mTLS 必須--client-ca
tls.self_signedboolfalsecert / key と同時指定はエラー(プロトタイプは黙って自己署名を優先していた)--self-signed
tls.self_signed_persistentboolfalseself_signed = true が必要--self-signed-persistent
tls.state_dirpath$XDG_STATE_HOME/qftp/self-signed(なければ ~/.local/state/qftp/self-signed)0700 で作成--self-signed-state-dir
limits.max_connectionsu32 ≥ 164--max-connections
limits.max_connections_per_ipu32 ≥ 18IPv4 /32、IPv6 /64--max-connections-per-ip
limits.initial_rate_rps / _burstf64 > 050 / 100Initial 用バケット--initial-rate-rps / --initial-rate-burst
limits.request_rate_rps / _burstf64 > 050 / 100要求用バケット--request-rate-rps / --request-rate-burst
limits.max_file_sizesize1 GiB≥ 1--max-file-size
limits.blocking_threadsu320(= CPU × 2)tokio max_blocking_threads--blocking-threads
limits.max_streams_bidiu32 ≥ 14QUIC transport parameter--max-streams-bidi
limits.idle_timeoutduration30s--idle-timeout
limits.half_open_timeoutduration5s未確立接続の破棄--half-open-timeout
limits.ls_page_entries / ls_page_bytesu32 / size10000 / 1 MiB1 ページの上限(entries ≤ 100000)--ls-page-entries / --ls-page-bytes
log.formatenumtexttext | json--log-format
log.levelstringinfotracing の EnvFilter 構文。RUST_LOG が優先--log-level

qftp-client: config.toml

# ~/.qftp/config.toml
[defaults]
compress = true
bwlimit = "0"                      # 0 = 無制限。上下双方向
tofu = false                       # true で --trust-on-first-use 相当
tofu_accept_new = false            # 非対話でも初回 pin を自動受理
zero_rtt = true
ticket_dir = "~/.qftp/session-tickets"
known_hosts = "~/.qftp/known_hosts"
history = "~/.qftp_history"
fail_fast = true                   # batch / -e
connect_timeout = "8s"             # アドレスごとのハンドシェイク予算

[host.work]
endpoint = "qftps://files.work.example:4433/data"   # user@ / :port / /path を含められる
host = "files.work.example"        # endpoint より優先
port = 4433
server_name = "files.work.example" # SNI とホスト名検証
ca = "~/.qftp/work-ca.pem"
client_cert = "~/.qftp/work-cert.pem"
client_key = "~/.qftp/work-key.pem"
initial_path = "/data"
insecure = false
tofu = false
compress = true
bwlimit = "10M"
キー型既定備考
[defaults].compressbooltrue--no-compress で false
[defaults].bwlimitsize/s0--bwlimit
[defaults].tofu / tofu_accept_newboolfalse / false-T / --tofu-accept-new
[defaults].zero_rttbooltrue--no-zero-rtt で false
[defaults].ticket_dir / known_hosts / historypath~/.qftp/…対応フラグあり
[defaults].fail_fastbooltrue--no-fail-fast
[defaults].connect_timeoutduration8s最後のアドレスは QUIC idle に委ねる
[host.*].endpointURLなしqftp:// / qftps://。パスワード付きは拒否。user@ は将来用に保持
[host.*].host / port / server_namestring / u16 / stringendpoint から明示キーが endpoint に勝つ
[host.*].ca / client_cert / client_keypathなしcert と key は対で必須
[host.*].initial_pathstringなし接続後に Cd
[host.*].insecureboolfalsetrue にできるだけで、CLI から false に戻す手段はない(--insecure は true のみ)
[host.*].tofu / compress / bwlimit[defaults]エイリアス単位の上書き

解決の例: qftp-client --bwlimit 1M work は、[defaults] → [host.work].endpoint(host / port / server_name / initial_path)→ [host.work] の明示キー → フラグ --bwlimit の順に上書きされ、最終的に bwlimit = 1M、initial_path = /data になります。

qftp-admin / qftp-web-bridge

プログラムフラグ既定
qftp-admin--users <path>/etc/qftp/users.toml
qftp-admin--tokens <path>/etc/qftp/tokens.toml
qftp-admin--mode <octal>0600(書込後のファイルモード)
# /etc/qftp/web-bridge.toml(Web 区分)
bind = "0.0.0.0:4433"
http_bind = "127.0.0.1:8080"      # 開発用 SPA 配信。省略時は無効
root = "/srv/qftp"
users = "/etc/qftp/users.toml"
tokens = "/etc/qftp/tokens.toml"  # 省略時は anonymous(read-only)のみ
allowed_origins = ["https://files.example.com"]   # [] = 未設定、["*"] = 全許可

[tls]
cert = "/etc/qftp/server.crt"
key = "/etc/qftp/server.key"

[limits]
max_sessions = 256
max_streams_per_session = 64
auth_timeout = "10s"
auth_failures_per_ip = 10         # 1 分あたり
max_file_size = "1Gi"
