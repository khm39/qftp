# シーケンス設計書 セクション仕様

## 1. 概要 (overview)
- シーケンス名 (name): このシーケンスの名称（例: 注文確定処理）
- 起点となるユースケース (use-case): どのユーザー操作・イベントが起点か
- 目的 (purpose): このシーケンスが果たす業務的・技術的役割
- 適用範囲 (scope): 対象とする処理の開始点と終端

## 2. 前提条件 (preconditions)
- 事前状態 (initial-state): 処理開始時にシステムが満たすべき状態
- 入力データ (inputs): 起点で渡される入力・パラメータ
- 認証・認可状態 (auth-state): 認証済みか、必要な権限は何か

## 3. 登場要素 (actors)
- アクター (actors): ユーザー・外部システム・外部サービス
- 内部コンポーネント (components): 関与するサービス・モジュール・DBなど
- 役割 (roles): 各要素が何を担うか

## 4. 処理ステップ (steps)
- 主要フロー (main-flow): ハッピーパスを番号付きステップで（誰が何をするか）
- 同期/非同期の判別 (sync-async): どこが同期呼び出し・非同期通知か
- 状態遷移 (state-transitions): 処理中に変わるエンティティ・リソースの状態
- トランザクション境界 (transaction-boundary): どこからどこまでが1トランザクションか

## 5. シーケンス図 (diagram)
- 図ファイル (diagram-link): drawio (`.drawio`) ファイルへの相対パス
- 図の概要 (diagram-summary): 図に何が描かれているかの説明（図を見ずとも本文だけで理解できるよう補足）

## 6. 異常系 (exceptional-flows)
- 失敗ケース (failure-cases): 起こりうる失敗パターンと検知点
- タイムアウト・リトライ (timeout-retry): タイムアウト値・リトライ回数・バックオフ戦略
- 補償処理 (compensation): ロールバック・補償トランザクション・整合性回復手順
- 部分失敗 (partial-failure): 中間ステップ失敗時の状態とリカバリ方針

## 7. 非機能要件 (non-functional)
- 想定レイテンシ (latency): エンドツーエンドの目標応答時間
- 冪等性 (idempotency): 同一リクエストの再送に対する挙動・キー設計
- 排他制御・並行性 (concurrency): 同時実行されたときの整合性確保方法
- 監査・ログ (audit): 残すべき監査ログ・トレースの粒度

## 8. 関連資料 (references)
- 関連設計書 (related-docs): 機能設計書・アーキテクチャ設計書など
- 外部設計成果物 (artifacts): drawio (シーケンス図本体)・OpenAPI 等の相対パスまたはURL
